# MCP Server Everything — 核心流程中文总结

> 基于 `@modelcontextprotocol/server-everything` 源码分析。
> 本项目是 MCP 官方 Reference Server，覆盖了 MCP 协议的全部能力。

---

## 一、整体架构

```
                    ┌──────────────────────────────────────┐
                    │           CLI 入口 (index.ts)          │
                    │   node index.js [stdio|sse|streamHttp] │
                    └──────┬───────────┬───────────┬────────┘
                           │           │           │
                    ┌──────▼──┐  ┌─────▼─────┐ ┌──▼──────────┐
                    │  STDIO  │  │    SSE    │ │ Streamable  │
                    │Transport│  │ Transport │ │ HTTP Transp │
                    └────┬────┘  └─────┬─────┘ └──────┬──────┘
                         │             │               │
                         └──────┬──────┴───────────────┘
                                │
                     ┌──────────▼──────────┐
                     │   Server Factory    │
                     │  (server/index.ts)  │
                     │   createServer()    │
                     └─────────────────────┘
                                │
              ┌─────────────────┼─────────────────┐
              │                 │                  │
     ┌────────▼──────┐  ┌──────▼──────┐  ┌───────▼──────┐
     │  registerTools│  │registerResrc│  │registerPrompts│
     │  无条件(12个)  │  │ 模板/文件/会话│ │ 无参/有参/补全 │
     │  条件(6个)     │  │ 订阅管理    │  │ 内嵌资源      │
     └───────────────┘  └─────────────┘  └──────────────┘
```

**核心设计原则：**
- **Server Factory 模式**：`createServer()` 是唯一创建入口，返回 `{ server, cleanup }`
- **Transport 与 Server 分离**：Server 只管逻辑，Transport 只管网络，可灵活切换
- **工具按能力注册**：Tool 分为「无条件」（立即注册）和「条件」（等客户端 capability 确认后注册）

## 三、Server 生命周期

```
1. CLI 启动
   ↓
2. Transport Manager 创建传输层（StdioServerTransport / SSEServerTransport / StreamableHTTPServerTransport）
   ↓
3. createServer() 创建 McpServer 实例
   ├── 配置 name/version
   ├── 声明 capabilities（tools/prompts/resources/logging/tasks 等）
   ├── 注册无条件工具 registerTools()
   ├── 注册资源 registerResources()
   ├── 注册提示 registerPrompts()
   └── 设置订阅处理器 setSubscriptionHandlers()
   ↓
4. server.connect(transport)   ← 建立 MCP 连接
   ↓
5. 初始化握手（initialize → initialized）
   ↓
6. server.oninitialized 回调
   ├── registerConditionalTools()  ← 注册依赖客户端能力的工具
   └── syncRoots()               ← 同步客户端 roots
   ↓
7. 运行中...（工具调用、资源读取、prompt 生成、日志推送、订阅通知等）
   ↓
8. 关闭 / 断连
   ├── cleanup(sessionId)
   │   ├── stopSimulatedLogging()
   │   └── stopSimulatedResourceUpdates()
   └── server.close()
```

## 四、核心 API 汇总

### 4.1 创建 Server

```ts
import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js";

const server = new McpServer(
  { name: "xxx", version: "1.0.0" },           // 身份信息
  {
    capabilities: {                              // 声明能力
      tools: { listChanged: true },
      resources: { subscribe: true, listChanged: true },
      prompts: { listChanged: true },
      logging: {},
      tasks: { list: {}, cancel: {}, requests: { tools: { call: {} } } },
    },
    instructions: "...",                          // 给 LLM 看的说明
    taskStore: new InMemoryTaskStore(),           // Tasks 支持（可选）
    taskMessageQueue: new InMemoryTaskMessageQueue(),
  }
);
```

### 4.2 注册 Tool

| API | 说明 |
|-----|------|
| `server.registerTool(name, config, callback)` | 注册普通 Tool |
| `server.experimental.tasks.registerToolTask(name, config, callback)` | 注册 Task-based Tool（异步长运行） |

**Tool config 结构：**
```ts
{
  title: "标题",
  description: "描述",
  inputSchema: z.object({ ... }),          // Zod schema（输入参数 + 文档）
  outputSchema: z.object({ ... }),         // Zod schema（结构化输出，可选）
  annotations: {                           // 工具行为标注
    readOnlyHint: true,                    // 只读？
    destructiveHint: false,                // 破坏性？
    idempotentHint: true,                  // 幂等？
    openWorldHint: false,                  // 与外部系统交互？
  },
}
```

**Tool callback 签名：**
```ts
async (args, extra): Promise<CallToolResult> => {
  // args: 已验证的输入参数
  // extra: { sessionId, requestId, _meta, sendRequest() }
  return {
    content: [                                   // 向后兼容
      { type: "text", text: "..." },
      { type: "image", data: base64, mimeType: "image/png" },
      { type: "resource", resource: { uri, mimeType, text/blob } },
      { type: "resource_link", uri, name, mimeType },
    ],
    structuredContent: { ... },                  // 结构化输出（可选）
  };
}
```

### 4.3 注册 Resource

| API | 说明 |
|-----|------|
| `server.registerResource(name, uri, metadata, callback)` | 注册单个静态资源 |
| `server.registerResource(name, new ResourceTemplate(uriTemplate, opts), metadata, callback)` | 注册 URI 模板资源（动态） |

**ResourceTemplate 选项：**
- `list: undefined` → 不暴露在资源列表中（仅模板访问）
- `complete: { resourceId: completer }` → 变量自动补全

**Resource callback 返回格式：**
```ts
{ contents: [{ uri: "...", mimeType: "text/plain", text: "..." }] }
// 或 blob 类型
{ contents: [{ uri: "...", mimeType: "application/octet-stream", blob: "base64..." }] }
```

### 4.4 注册 Prompt

```ts
server.registerPrompt(name, config, callback);

// config:
{
  title: "标题",
  description: "描述",
  argsSchema: { city: z.string(), state: z.string().optional() },
}

// callback 返回:
{
  messages: [
    { role: "user", content: { type: "text", text: "..." } },
    { role: "user", content: { type: "resource", resource: {...} } },  // 内嵌资源
  ]
}
```

**completable 包装：**
```ts
import { completable } from "@modelcontextprotocol/sdk/server/completable.js";

const department = completable(
  z.string().describe("选部门"),
  (value, context) => {
    // context.arguments 可读取其他参数的值，实现级联补全
    return ["Engineering", "Sales"].filter(d => d.startsWith(value));
  }
);
```

### 4.5 Server ↔ Client 通信

| API | 说明 |
|-----|------|
| `server.sendLoggingMessage({ level, data }, sessionId?)` | 向客户端发送日志 |
| `server.server.notification({ method, params })` | 发送通知（如资源更新、进度） |
| `extra.sendRequest(request, schema)` | Tool 内向客户端发送请求（elicitation/sampling） |
| `server.server.getClientCapabilities()` | 获取客户端能力列表 |
| `server.server.setRequestHandler(schema, handler)` | 设置请求处理器（如 subscribe/unsubscribe） |
| `server.server.setNotificationHandler(schema, handler)` | 设置通知处理器（如 roots/list_changed） |

### 4.6 条件注册模式

```ts
export const registerXxxTool = (server: McpServer) => {
  const caps = server.server.getClientCapabilities() || {};
  if (caps.sampling !== undefined) {   // 只有在客户端声明支持时才注册
    server.registerTool(name, config, callback);
  }
};
```

## 五、Transport 层对比

| 特性 | STDIO | SSE | Streamable HTTP |
|------|-------|-----|-----------------|
| 并发客户端 | 单进程单连接 | 多会话（Map<sessionId, transport>） | 多会话 |
| 端点 | stdin/stdout | GET /sse, POST /message | POST/GET/DELETE /mcp |
| sessionId | 无/undefined | 有（自动生成） | 有（header `mcp-session-id`） |
| 断线重连 | 不支持 | 不支持 | 支持（Last-Event-ID） |
| Elicitation | ✅ | ❌（sendRequest 不可用） | ❌（待 SDK PR#1210） |
| 适用场景 | 本地开发、CLI 工具 | Web 多客户端 | 生产环境 |

**Streamable HTTP 是推荐的传输方式**，支持：
- POST：JSON-RPC 请求
- GET：SSE 流（含 `Last-Event-ID` 重连）
- DELETE：会话终止

## 七、Content 类型总结

Tool 返回的 `content` 数组支持以下 content block 类型：

| type | 用途 | 示例 |
|------|------|------|
| `text` | 纯文本 | `{ type: "text", text: "Hello" }` |
| `image` | 图片（base64） | `{ type: "image", data: "...", mimeType: "image/png" }` |
| `resource` | 内嵌资源 | `{ type: "resource", resource: { uri, mimeType, text/blob } }` |
| `resource_link` | 资源引用 | `{ type: "resource_link", uri, name, mimeType }` |

Content block 可附带 `annotations`：`{ priority: 0-1, audience: ["user"|"assistant"] }`

## 八、关键设计模式

1. **Factory + Cleanup**：`createServer()` 返回 `{ server, cleanup }`，由 Transport 层管理生命周期
2. **能力协商**：`getClientCapabilities()` → 决定是否注册某些工具
3. **Session 隔离**：通过 `sessionId` 区分多客户端，Map 结构存储每会话状态
4. **动态资源**：Tool 运行时可通过 `registerSessionResource` 创建临时资源
5. **订阅-通知**：`setSubscriptionHandlers` + 定时器驱动的 `notifications/resources/updated`
6. **completable 包装**：给参数添加自动补全，第二个参数可依赖第一个参数的值（级联补全）

## 九、MCP 协议能力清单

本项目覆盖的 MCP 协议能力及其对应实现位置。

### 9.1 能力总览

| 能力分类 | 协议能力 | 声明方式 | 本项目实现 |
|----------|----------|----------|-----------|
| **Tools** | `tools` | `capabilities.tools: {}` | 18 个示例 Tool（12 无条件 + 6 条件） |
| | `tools.listChanged` | `capabilities.tools: { listChanged: true }` | 条件工具初始化后注册，列表随之变化 |
| **Prompts** | `prompts` | `capabilities.prompts: {}` | 4 种模式：无参/有参/补全/内嵌资源 |
| **Resources** | `resources` | `capabilities.resources: {}` | 静态文件/模板/会话级 等 4 种模式 |
| | `resources.subscribe` | `capabilities.resources: { subscribe: true }` | 订阅管理 + 模拟更新通知 |
| | `resources.listChanged` | `capabilities.resources: { listChanged: true }` | 动态资源的列表变化通知 |
| **Logging** | `logging` | `capabilities.logging: {}` | 8 个日志级别的模拟推送 |
| **Tasks** | `tasks.list` | `capabilities.tasks: { list: {} }` | 任务列表查询 |
| | `tasks.cancel` | `capabilities.tasks: { cancel: {} }` | 任务取消 |
| | `tasks.requests` | `capabilities.tasks: { requests: { tools: { call: {} } } }` | 双向 Tasks（服务端也可请求客户端执行） |
| **Sampling** | `sampling` | 客户端声明，服务端检查 | `trigger-sampling-request` 条件工具 |
| **Elicitation** | `elicitation` | 客户端声明，服务端检查 | `trigger-elicitation-request` 条件工具 |
| **Roots** | `roots` | 客户端声明，服务端检查 | `get-roots-list` 条件工具 |

### 9.2 各能力详解

#### Tools（工具）

最核心的 MCP 能力。客户端调用服务端暴露的函数。

| 项 | 说明 |
|----|------|
| 注册 API | `server.registerTool(name, config, async (args, extra) => {...})` |
| 注册 Task Tool | `server.experimental.tasks.registerToolTask(...)` |
| 输入校验 | `config.inputSchema` — Zod schema，SDK 自动校验 |
| 结构化输出 | `config.outputSchema` — Zod schema，可选 |
| 行为标注 | `config.annotations: { readOnlyHint, destructiveHint, idempotentHint, openWorldHint }` |
| callback extra | `{ sessionId, requestId, _meta, sendRequest() }` |
| 返回类型 | `CallToolResult = { content: ContentBlock[], structuredContent?, _meta? }` |
| 对应文件 | `tools/*.ts`（18 个文件） |

#### Resources（资源）

服务端暴露数据给客户端，类似"只读文件系统"的抽象。

| 项 | 说明 |
|----|------|
| 静态资源 | `server.registerResource(name, uri, metadata, callback)` |
| 模板资源 | `new ResourceTemplate("uri/{var}", { list: undefined, complete: {...} })` |
| 会话资源 | 运行时通过 `registerSessionResource()` 动态注册，连接断开即销毁 |
| 返回格式 | `{ contents: [{ uri, mimeType, text }] }` 或 `{ contents: [{ uri, mimeType, blob }] }` |
| 自动补全 | `completable(z.string(), filterFn)` 给 URI 变量添加补全 |
| 对应文件 | `resources/templates.ts`, `files.ts`, `session.ts` |

#### Resource Subscribe（资源订阅）

客户端订阅某 URI 的更新通知，服务端主动推送变更。

| 项 | 说明 |
|----|------|
| 订阅处理 | `server.server.setRequestHandler(SubscribeRequestSchema, handler)` |
| 取消订阅 | `server.server.setRequestHandler(UnsubscribeRequestSchema, handler)` |
| 推送通知 | `server.server.notification({ method: "notifications/resources/updated", params: { uri } })` |
| 会话隔离 | `Map<uri, Set<sessionId>>`，每会话独立维护 |
| 对应文件 | `resources/subscriptions.ts` |

#### Prompts（提示模板）

服务端提供预设提示词，客户端/LLM 可选择并参数化。

| 项 | 说明 |
|----|------|
| 注册 | `server.registerPrompt(name, config, (args) => ({ messages }))` |
| 普通参数 | `argsSchema: { city: z.string(), state: z.string().optional() }` |
| 自动补全 | `argsSchema: { department: completable(z.string(), fn) }` |
| 级联补全 | 第二个参数的 `completable` 回调可通过 `context.arguments.department` 读取第一个参数的值 |
| 内嵌资源 | prompt 消息可包含 `{ type: "resource", resource: {...} }` |
| 对应文件 | `prompts/simple.ts`, `args.ts`, `completions.ts`, `resource.ts` |

#### Logging（日志推送）

服务端主动向客户端推送日志消息，由客户端控制接收级别。

| 项 | 说明 |
|----|------|
| 推送 API | `server.sendLoggingMessage({ level, logger?, data }, sessionId?)` |
| 级别控制 | 客户端通过 `logging/setLevel` 设置最小级别，SDK 自动过滤 |
| 可用级别 | debug, info, notice, warning, error, critical, alert, emergency |
| 对应文件 | `server/logging.ts`, `tools/toggle-simulated-logging.ts` |

#### Sampling（LLM 采样）

服务端请求客户端调用 LLM（服务端不直接调 LLM API）。

| 项 | 说明 |
|----|------|
| 调用方式 | `extra.sendRequest({ method: "sampling/createMessage", params: {...} }, CreateMessageResultSchema)` |
| 前置条件 | 客户端声明 `capabilities.sampling` |
| 请求参数 | `messages[]`, `systemPrompt?`, `maxTokens`, `temperature`, `stopSequences?`, ... |
| 对应文件 | `tools/trigger-sampling-request.ts` |

#### Elicitation（用户交互）

服务端在执行过程中向用户发起表单式提问。

| 项 | 说明 |
|----|------|
| 调用方式 | `extra.sendRequest({ method: "elicitation/create", params: { message, requestedSchema } }, ElicitResultSchema)` |
| 前置条件 | 客户端声明 `capabilities.elicitation` |
| Schema | JSON Schema 描述表单（string/boolean/integer/date/email/enum 等） |
| 结果 | `{ action: "accept" | "decline" | "cancel", content? }` |
| 局限 | 当前仅 STDIO transport 可用，SSE/HTTP 待 SDK 完善 |
| 对应文件 | `tools/trigger-elicitation-request.ts` |

#### Roots（根目录）

客户端向服务端暴露文件系统根目录列表。

| 项 | 说明 |
|----|------|
| 获取 | `server.server.listRoots()` → `{ roots: Root[] }` |
| 变更监听 | `server.server.setNotificationHandler(RootsListChangedNotificationSchema, handler)` |
| 缓存 | 每会话首次拉取后缓存，变更时刷新 |
| 前置条件 | 客户端声明 `capabilities.roots` |
| 对应文件 | `server/roots.ts`, `tools/get-roots-list.ts` |

#### Tasks（异步任务）

支持长时间运行的操作，避免超时阻塞。MCP 协议层面基于 SEP-1686 提案。

| 项 | 说明 |
|----|------|
| 注册 | `server.experimental.tasks.registerToolTask(...)`（实验性 API） |
| 流程 | 调用带 `task: true` → `CreateTaskResult { taskId }` → 轮询 `tasks/get` → 取 `tasks/result` |
| 状态机 | `working` → `input_required`（可选）→ `completed` / `failed` / `cancelled` |
| 存储 | `InMemoryTaskStore` + `InMemoryTaskMessageQueue` |
| 双向 Tasks | 服务端请求客户端执行任务：在请求参数中附带 `params.task.ttl` |
| 对应文件 | `tools/simulate-research-query.ts`, `trigger-*-async.ts` |

### 9.3 能力协商流程

```
Server（服务端）                  Client（客户端）
  │                                │
  │  createServer() 声明自己的      │
  │  capabilities（我提供什么）      │
  ├── connect ────────────────────►│
  │◄── initialize ────────────────│ 客户端声明 capabilities（我需要什么）
  │    { capabilities: {           │
  │      sampling, elicitation,    │
  │      roots, experimental       │
  │    }}                          │
  │                                │
  │  oninitialized 回调:           │
  ├── getClientCapabilities()      │ ← 读取客户端声明
  ├── 注册条件工具                   │
  ├── syncRoots()                  │
  │                                │
  ├── initialized ────────────────►│
  │                                │
  │  ★ 正常运行 ★                   │
```

**核心概念**：
- 服务端声明的 capabilities = **我提供什么服务**
- 客户端声明的 capabilities = **我需要哪些额外能力**（sampling、elicitation、roots 等是服务端"请求"客户端的能力）
- `getClientCapabilities()` = 能力协商的关键桥梁
|----------|----------|----------|-----------|
| **Tools** | `tools` | `capabilities.tools: {}` | 18 个示例 Tool |
| | `tools.listChanged` | `capabilities.tools: { listChanged: true }` | 条件注册工具在初始化后动态改变列表 |
| **Prompts** | `prompts` | `capabilities.prompts: {}` | 4 种 Prompt 模式 |
| | `prompts.listChanged` | `capabilities.prompts: { listChanged: true }` | （声明但不演示） |
| **Resources** | `resources` | `capabilities.resources: {}` | 静态/模板/会话/文件 4 种资源 |
| | `resources.subscribe` | `capabilities.resources: { subscribe: true }` | 订阅管理 + 模拟更新通知 |
| | `resources.listChanged` | `capabilities.resources: { listChanged: true }` | 动态资源列表变化 |
| **Logging** | `logging` | `capabilities.logging: {}` | 模拟多级别日志推送 |
| **Tasks** | `tasks` | `capabilities.tasks: {}` | 异步长运行工具 |
| | `tasks.list` | `capabilities.tasks: { list: {} }` | 任务列表查询 |
| | `tasks.cancel` | `capabilities.tasks: { cancel: {} }` | 任务取消 |
| | `tasks.requests` | `capabilities.tasks: { requests: { tools: { call: {} } } }` | 双向 Tasks（服务端请求客户端执行） |
| **Sampling** | `sampling` | （客户端声明，服务端检查） | `trigger-sampling-request` 演示 |
| **Elicitation** | `elicitation` | （客户端声明，服务端检查） | `trigger-elicitation-request` 演示 |
| **Roots** | `roots` | （客户端声明，服务端检查） | `get-roots-list` 演示 |
